# Apple developer docs — local digests

Trimmed markdown digests of Apple `developer.apple.com` documentation, saved for this
phone-in-headset VR project. Each file starts with its source URL(s) and fetch date, and keeps
symbol names, signatures, and iOS availability markers (nav boilerplate dropped). Reuse these
before re-fetching; re-pull if Apple has likely changed the surface.

How these tie to the project: the experiments run as WebGL in an iOS `WKWebView` shell and get
head tracking from web `deviceorientation` events (`DeviceOrientationControls`), not native
ARKit. See `CLAUDE.md` and the `headset` skill (`ios-webview-wrapper-notes.md`). These docs
cover the **native** APIs and the **bridge** you'd use if native sensing ever needs to reach
the web scene.

Info.plist keys + how pixels reach our WebGL stereo. Bottom line: getUserMedia → `VideoTexture`.                                                                                                                                                            |
| `scene-depth.md`        | LiDAR scene depth  | Depth-reprojected stereo passthrough. Enabling: `FrameSemantics.sceneDepth`/`.smoothedSceneDepth`, `supportsFrameSemantics(_:)` (LiDAR-only). Reading: `ARFrame.sceneDepth`→`ARDepthData.depthMap` (`DepthFloat32`/`r32Float`, metres, ~256×192, depth=optical-axis Z) + `confidenceMap` (`ARConfidenceLevel` low/medium/high). Intrinsics/unprojection: `ARCamera.intrinsics` belong to `imageResolution` — must scale to depth res; depthMap & `capturedImage` share native-sensor (landscape) orientation; `projectionMatrix`/`viewMatrix`/`displayTransform` are render helpers. Native-Metal-only; not a WebGL drop-in. |

| `face-tracking.md` | Face tracking | Front-camera face sensing. `ARFaceTrackingConfiguration` (`isSupported`; Neural Engine on iOS 14+ vs TrueDepth on iOS 13-; ~3 m range; `maximumNumberOfTrackedFaces` defaults to 1, ceiling `supportedNumberOfTrackedFaces`, iOS 13+; privacy-policy requirement). `ARFaceAnchor`: right-handed face coordinate space (metres, origin behind the face), `geometry`, `blendShapes`, `leftEyeTransform`/`rightEyeTransform` + `lookAtPoint` (iOS 12+, length encodes focus distance), `isTracked`. `ARFaceGeometry` constant topology (only `vertices` changes) + `init(blendShapes:)`. `ARSCNFaceGeometry` (Metal-only) with `update(from:)`, `fillMesh`, and the `colorBufferWriteMask = []` + `renderingOrder = -1` occlusion recipe. Camera-video-onto-face texture mapping via a `geometry` shader modifier + inverted `displayTransform` (carries the front-camera flip). All 52 `BlendShapeLocation` constants by region (`tongueOut` iOS 12+). Simultaneous world+face both directions (`userFaceTrackingEnabled` / `isWorldTrackingEnabled`, iOS 13+). Gotchas incl. the in-headset blocker and what is/isn't bridgeable to the WebView. |
| `hand-tracking.md` | Hand tracking | Hands across BOTH frameworks, because they don't overlap. **visionOS ARKit**: `HandTrackingProvider` (`isSupported`, `anchorUpdates` vs `latestAnchors` vs `handAnchors(at:)`), `ARKitSession` + `requestAuthorization(for:)` with the `.handTracking`/`.worldSensing`/`.cameraAccess`/`.accessoryTracking` cases, `NSHandsTrackingUsageDescription`, `DataProviderState`; `HandAnchor` (`chirality`, optional `handSkeleton`, `originFromAnchorTransform`, `isTracked`, `fidelity`); `HandSkeleton.Joint` (`anchorFromJointTransform` vs `parentFromJointTransform`) + all 27 `JointName` cases (thumb has 4, not 5) and a pinch-distance recipe. **All visionOS 1.0+ — none of it exists on iOS.** **iOS Vision**: `VNDetectHumanHandPoseRequest` (iOS 14+, `maximumHandCount` default 2 and it gates inference, not just output), `VNHumanHandPoseObservation` (throwing `recognizedPoint`, `chirality` iOS 15+), all 21 `JointName`s by group, the **lower-left** normalized origin (undocumented on the API pages; WWDC-sourced), lifting 2D points to 3D via `sceneDepth`, and the throttle/background-queue cost notes. 12 gotchas. |
| `room-scanning.md` | RoomPlan | Parametric room scanning (NOT a mesh — oriented bounding boxes + labels; no vertex data in the API). Three tiers: `RoomCaptureView` drop-in UI, `RoomCaptureSession` + delegate (note `didUpdate` is the full snapshot, `didAdd`/`didRemove`/`didChange` are deltas), and `RoomBuilder`/`CapturedRoomData` for deferred/off-device processing. Data model: `Surface` (`completedEdges` as a per-edge quality signal, `curve`, iOS 17 `polygonCorners` + `parentIdentifier`), `Object` (16 fixed furniture categories; attributes only for chair/sofa/storage/table), `Section` = functional areas WITHIN one room. **Units, origin, axes and `transform` column order are undocumented** — metres/+Y-up is ARKit inference, the column convention is forum folklore. Multi-room `CapturedStructure`/`StructureBuilder` (iOS 17) with the `stop(pauseARSession:false)` footgun and relocalization cost. Export: `.parametric` does NOT cut door/window holes, `.mesh` does; pre-17.4 digit-first filename bug. LiDAR required (`isSupported` is the only real gate), iOS/iPadOS/Mac Catalyst only — **no visionOS**; Catalyst silently no-ops capture. All numeric limits (9×9 m, 2000 sq ft, 5 min, 50 lux) are WWDC-only, never documented. |
| `placement-correction.md` | Placement correction | Heuristic drop-to-floor + wall-clip nudge for the native renderer (no physics). `ARPlaneAnchor` (`center`/`extent`/`planeExtent`/`geometry.boundaryVertices`/`alignment`/`classification`) point-in-plane + plane-normal push; `ARRaycastQuery`/`ARSession.raycast` (`.existingPlaneGeometry`/`.existingPlaneInfinite`/`.estimatedPlane`, `.horizontal`/`.vertical`) for downward floor-Y and horizontal wall probes; `ARMeshAnchor`/`sceneReconstruction = .mesh` (NOT enabled today — cost/value note) for non-planar clearance; direct `sceneDepth.depthMap` sampling as a view-dependent live check. Ranked recos, Swift sketches, iOS-mins, and the iOS-16 plane-rotation + extent-vs-infinite gotchas. |
