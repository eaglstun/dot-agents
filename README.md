# dot-agents

The public slice of my `~/.agents` — skills, agents, hooks,
and output styles that are actually reusable by someone who isn't me.

This branch is **generated**. It is rebuilt from scratch on every publish by
`publish.sh`, which copies only skills marked `metadata.public: true` and agents marked
`public: true`,
strips machine-specific paths, and refuses to push if an audit finds a
credential, a private IP, or a personal path. My working config lives on a
private branch that is never pushed anywhere.

## Layout and harness compatibility

- `skills/<name>/SKILL.md` uses the Agent Skills format Codex expects: `name` and
  `description` at the top level, with local fields such as `version`, `public`, and
  semantic IDs under `metadata`.
- Codex discovers ordinary user skills directly from `~/.agents/skills`; no
  `~/.codex/skills` symlink is needed for those skills.
- `agents/<name>.md` is the Claude agent definition. The matching
  `agents/<name>.toml` is the Codex custom-agent definition and contains Codex's
  required `name`, `description`, and `developer_instructions` fields.
- Codex custom agents still need links under `~/.codex/agents`; Claude agents need
  links under `~/.claude/agents`.
- `hooks/` and `output-styles/` are Claude-facing. Codex settings, MCP servers,
  and approvals remain in `~/.codex`.
- The harness-neutral user instructions live in this repository's `AGENTS.md`.
  `~/.codex/AGENTS.md` and `~/.claude/CLAUDE.md` link to that shared source.

## Install or link

```bash
git clone git@github.com:eaglstun/dot-agents.git ~/.agents

mkdir -p ~/.codex/agents ~/.codex/skills ~/.claude/agents ~/.claude/skills

ln -sfn ~/.agents/AGENTS.md ~/.codex/AGENTS.md
ln -sfn ~/.agents/AGENTS.md ~/.claude/CLAUDE.md

# Codex reads ordinary skills from ~/.agents/skills natively. Only its custom
# agents need links.
for file in ~/.agents/agents/*.toml; do
  ln -sfn "$file" ~/.codex/agents/"$(basename "$file")"
done

# Claude needs links for both skills and Markdown agent definitions.
for dir in ~/.agents/skills/*; do
  [ -f "$dir/SKILL.md" ] || continue
  ln -sfn "$dir" ~/.claude/skills/"$(basename "$dir")"
done
for file in ~/.agents/agents/*.md; do
  ln -sfn "$file" ~/.claude/agents/"$(basename "$file")"
done
```

Or cherry-pick a single skill — they're self-contained.

After editing a Markdown agent, regenerate or check its Codex counterpart:

```bash
python3 scripts/sync-agent-formats.py agent-name
python3 scripts/sync-agent-formats.py --check
```
